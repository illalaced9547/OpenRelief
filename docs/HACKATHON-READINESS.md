**What is already strong.** The dataset has 9,065 training examples across 16 countries, 2,503 validation examples, and 2,230 test examples across 14 countries. Six-month windows, release-lag masking, purged label boundaries, explicit observation masks and checksummed artifacts support a credible retrospective benchmark. Temporal and connector tests cover meaningful failure modes. The reusable acquisition package is a tangible contribution independent of whether a model beats persistence. Existing annotations cover 30.68% of training; incomplete annotation is not itself a challenge failure because the slides specify no minimum annotation count.

**Important implementation and evidence gaps.**

1. **The training cohort is ambiguous.** The shipping report says training used 2,781 examples. The current [GPU runner](../src/open_relief/gpu.py) loads all 9,065 training examples and supplies empty rationales/actions for unannotated examples. An alternate dataset or remote code version may explain this. Check the actual run before claiming either training count. With the current dataset, 6,284 examples train on empty language targets, which could work against explanation generation; this is a risk to inspect in outputs, not a measured failure.
2. **Ablation supervision can still mention the removed source.** [The adapter](../src/open_relief/adapter.py) drops source channels from inputs but retains the full rationale and recommended-action target. A no-shipping run may therefore learn to discuss shipping without observing it. These runs do not isolate channel information as cleanly as source-consistent supervision would. Inspect actual remote code and outputs; document the limitation. Only repeat training if there is enough time after delivering the main model and demo.
3. **Language and action validity are not evaluated.** [Prediction parsing](../src/open_relief/evaluate.py) checks phase and rationale type, but does not require actions or assess grounding. Training converts structured actions into strings, losing machine-readable urgency, driver references and justification. Audit generated outputs before promising those capabilities. Schema-valid teacher output is not a quality score for the trained model.
4. **The annotation validator does not enforce all of its prompt's grounding rules.** An offline linkage check found 44 actions across 41 training annotations with at least one driver channel absent from their precursor/interaction citations. Current validation accepts them because the channel exists in the input schema. This establishes a citation-linkage defect, not that all 44 actions are factually wrong. Review or filter these rows before any further language-focused fine-tuning.
5. **Retrospective teacher phrasing can become misleading forecast language.** Sample rationales explicitly call the future phase a supplied outcome. This is allowed in training supervision and does not place the future label in inference inputs, but the model should not present its own forecast as a known future observation. Review generated phrasing and keep observed outcomes hidden in the demo until the reveal.
6. **The generation limit needs a quick check.** The runner permits 256 new tokens. Teacher rationale plus action text has a median of 141 words and a maximum of 195, before JSON/tokenization overhead. That does not prove truncation, but makes raw-output inspection important, especially for missing actions or invalid JSON. If changing the limit, use the same generation configuration for compared models and record it.
7. **TimeNet should be visible in the demonstrated pipeline.** Native connectors genuinely exist, but `rebuild_local.sh` consumes monthly JSONL, and the GPU runner reads the custom multimodal dataset. A small verified bridge or a documented equality check from a TimeF export into one training example makes the TimeNet contribution easy to assess. A full data-format migration is unnecessary in four hours. The official [TimeNet architecture](https://github.com/OpenTSLM/TimeNet#how-it-fits-together) distinguishes connectors, the in-memory dataset and reader/writer; training is left to the consumer.
8. **Submission packaging is incomplete for the new remote work.** [The upload script](../scripts/upload_to_nebius.sh) transfers the multimodal dataset but not the required annotations. [The handoff allowlist](../scripts/package_handoff.py) includes neither the new Dockerfile nor GPU run directories/checkpoints. Merely rerunning it will not deliver all required model artifacts. Add explicit artifacts or separate documented download links. The existing archive predates the recent annotation work.
9. **Documentation conflicts with current code and artifacts.** README/STATUS describe annotation and GPU work as pending, the shipping report describes completed runs, and README says complete annotations are required although the runner accepts partial coverage. Publish one evidence-based status table. Historical release times and revisions remain unknown; national covariates do not demonstrate district exposure, and a three-month target horizon is not measured operational warning lead time.

The smallest compelling demo is a case selector and evidence panel, not an elaborate globe or a general chatbot. Use existing country/district identifiers rather than inventing precise map coordinates. Show the forecast cutoff and target month, available vs missing channels, last known IPC and its age, then the model's actual forecast and evidence-grounded text. Present recommendations as proposed analyst follow-up, preserving uncertainty. If the checkpoint does not generate useful actions, distinguish any separate rule-based or teacher-produced content clearly; do not present it as the TSLM's output.

A saved-inference replay is useful insurance and can power a functioning exploration interface, but it must be labeled. Prefer one genuine on-demand inference during the live demo if practical. A video alone does not establish the working-demo deliverable. If measuring usefulness, time a small analyst-style comparison of reading raw charts versus producing a checked briefing, and label the sample size and whether the reviewer is a domain expert. Do not invent user validation or lives-saved estimates.

**Pitch structure.** Establish the analyst's review problem; show one historical case before revealing its outcome; explain native multivariate inputs and reusable TimeNet connectors; give a same-cohort result table; show where the model succeeds and fails; close with the concrete reusable contribution and what the evidence supports. The strongest defensible story may be a transparent evidence-to-briefing workflow with competitive phase prediction, rather than a claimed breakthrough early-warning model. Whether the language actually adds value remains to be demonstrated from checkpoint outputs. The [OpenTSLM paper](https://arxiv.org/abs/2510.02410) motivates native time-series-and-language reasoning; it does not establish forecasting or intervention performance for this dataset.

**Defer during these four hours:** acquiring more countries or sources, a broad autonomous discovery agent, a larger backbone or architecture migration, completing all 9,065 annotations merely for completeness, extensive hyperparameter searches, and sweeping causal claims. A full annotation job is not necessary to meet the slides, and spending the remaining window there could prevent delivery of the required checkpoint/demo/evaluation package. A short corrective training run is justified only after inspecting outputs and confirming that the existing model cannot support the intended demo.
